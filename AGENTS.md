# AGENTS.md

This file provides guidance to AI coding agents working in this repository.

> Before making changes, always read `README.md` first (source of truth for architecture, requirements, and setup). If `COMMAND.md` exists, read it for reusable task templates. `COMMAND.md` defers to `README.md` on conflicts.

## Commands

### Backend (Rust / Loco)

```sh
cargo loco start                        # run the server (port 5150, auto-migrates)
cargo build                             # build
cargo test                              # run all tests
cargo test <test_name>                  # run a single test by name
cargo insta review                      # review / accept snapshot changes after tests
cargo loco generate scaffold <name> <fields> --api  # scaffold a new resource (model + controller + migration)
cargo loco generate model <name>        # generate model + migration only
cargo loco db migrate                   # run pending migrations
cargo loco db reset                     # drop and recreate the database
cargo fmt                               # format (max_width=100)
cargo clippy                            # lint
```

### Frontend (React / rsbuild)

```sh
cd frontend
npm run dev      # dev server with /api proxy to http://127.0.0.1:5150
npm run build    # production build → frontend/dist/ (served by the backend)
npm run lint     # Biome check
```

## Architecture

### Request flow

In development, the frontend rsbuild dev server (default port 3000) proxies all `/api/*` requests to the Rust backend at `http://127.0.0.1:5150`. In production, the Loco server serves `frontend/dist/` as static files and handles all `/api` routes itself.

### Backend layer structure

| Layer | Location | Purpose |
|---|---|---|
| Controllers | `src/controllers/` | Route registration + thin request parsing only |
| Models (generated) | `src/models/_entities/` | Auto-generated SeaORM entities — **never edit** |
| Models (extended) | `src/models/` | Business logic, finders, `ActiveModelBehavior` |
| Views | `src/views/` | Response/DTO structs (`Serialize`) |
| Services | `src/services/` *(add here)* | Complex business logic not tied to a single model |
| Workers | `src/workers/` | Background jobs (registered in `app.rs`) |
| Tasks | `src/tasks/` | CLI tasks (registered in `app.rs`) |
| Migrations | `migration/src/` | `sea-orm-migration` files; add to `Migrator` in `migration/src/lib.rs` |

### App bootstrap (`src/app.rs`)

`App` implements the Loco `Hooks` trait. Routes are wired in `fn routes()`, workers in `connect_workers()`, and tasks in `register_tasks()`. All scaffold-generated inject comments (`// inject-above`, `// tasks-inject`) must be kept intact.

### SeaORM entity pattern

`src/models/_entities/<name>.rs` is regenerated by `cargo loco generate`. Extend a model by adding methods to `Model` and `ActiveModel` in `src/models/<name>.rs`, which re-exports the entity types:

```rust
pub use super::_entities::<name>::{self, ActiveModel, Entity, Model};
```

### Auth

JWT-based. Token issued at login/magic-link, validated via `auth::JWT` extractor in protected handlers. JWT secret and expiration live in `config/<env>.yaml` (`auth.jwt`). Database connection URL is read from `DATABASE_URL` env var (default: `postgres://loco:loco@localhost:5432/jham_development`).

### Testing

Tests live in `tests/` split into `models/`, `requests/`, `tasks/`, and `workers/`. Snapshot assertions use `insta` (YAML format with redactions). After changing response shapes, run `cargo insta review` to update snapshots. Tests that touch the database must be run with `serial_test` to avoid parallel conflicts.

## Key conventions

- **company_id isolation**: every asset query must filter by `company_id`.
- **External IDs**: use UUID (`pid` / `uuid` columns), never expose raw integer PKs.
- **Rust style**: prefer straightforward, beginner-readable code — avoid unnecessary lifetimes or generics. Line width is 100 characters (`rustfmt.toml`).
- **New migrations**: name files `m<YYYYMMDD>_<HHMMSS>_<description>.rs` and register them in `migration/src/lib.rs` above the `// inject-above` comment.
